## Shared Absolute Date And Time Formatting

- `lib/utils/format.ts` owns `dateText(value,fallback)`, `timeText(value,fallback)` and `dateTimeText(value,fallback)`: `dd-mm-yyyy`, `HH:mm`, `HH:mm dd-mm-yyyy`. It accepts Date objects, epoch milliseconds and validated ISO date/date-time strings; `timeText` also accepts `HH:mm[:ss[.fraction]]`. Missing/invalid input returns the selected fallback (`-` by default), including invalid leap days and clocks. A date-only value returns only a date even through `dateTimeText`; `timeText` does not invent midnight for it.
- Timestamps with explicit offsets use a cached `Asia/Ho_Chi_Minh` formatter, with 24-hour clock and no seconds. Pure calendar dates and offset-free wall times are formatted directly, independent of device timezone. Input values, ISO payloads, numeric sorting/date arithmetic and exported machine data remain separate from display.
- Existing `dateText` consumers inherit the convention. Timeline/audit/BOQ use imports under their established local aliases; Work Item `compactDateTime` and Event Log `eventLogDateTime` are compatibility re-exports. Signature, Operations and Work Report wrappers preserve contextual placeholders. Staff export/date input serialization is unaffected. Warehouse/Procurement retain explicit calendar-date extraction; Rework/QA dates now have display renderers without changing sort/filter values. Absolute date fallback in notifications and activity-day labels also uses the helper.
- `activityThreadDomain.ts` groups and labels days against the same Vietnam calendar boundary; relative Today/Yesterday chat labels remain. Dashboard day groups always show the full date. Tests in `dateFormatting.test.ts` cover the shared contract and chat grouping; `dashboardActivity.test.ts` covers feed dates/paging/navigation.

## Global Utility Dock

Escape closes the picker first, then the one visible mobile surface or least-recently-expanded desktop surface; minimizing preserves the open project dock and its mounted state, per-window close removes only that project, and the picker owns the explicit close-all action.
- Desktop uses one right-anchored lane deck ordered `[open project conversations] [+ Trao đổi] [Làm ngay]`. The project region is the only horizontally scrollable area; its interactive strip is intrinsic-width, right-aligned while it fits and capped by the available region, while `+ Trao đổi` and `Làm ngay` remain fixed and visible at the right edge. Every project lane owns both its separately mounted conversation window and launcher and uses the same fixed 336px desktop width in expanded and minimized states. Project count never stretches a sparse session, and minimizing hides only the conversation without narrowing its dock. The strip uses proximity scroll snapping and automatically scrolls the newly opened or toggled project lane into view; constrained desktops show as many complete comfortable lanes as fit instead of compressing all five. The session keeps at most five project docks and rejects a sixth with a warning instead of evicting a dock or draft. At viewport width 1280px or above, the expansion budget permits five simultaneous surfaces even when the project strip must scroll; lower desktop breakpoints permit four, three or one, and opening beyond that budget minimizes only the least-recently-used expanded surface without closing its dock or unmounting a project conversation. From four open project docks, the fixed `+ Trao đổi` and minimized `Làm ngay` launchers compact to icon plus count. Each project pill toggles only its own window, shows its own unread/active emphasis and closes only that project. The project picker remains anchored immediately above `+ Trao đổi` and has an explicit `Đóng tất cả khung trao đổi` action. Mobile preserves one `Tiện ích` launcher and one visible full-width surface at a time while every open project's mounted state remains isolated and retained. Project discussion searches the actor-scoped project summary, renders visible project activity chronologically, highlights `is_discussion_unread`, advances only the explicit read-through cursor and reuses `ActivityComposer` plus reply/attachment presentation. It never treats mention attention as general new-message state. The Dock alone opts into `ActivityComposer density="compact"`: one bordered composer contains a thin on-demand target row, a 44–112px auto-growing non-resizable message field, one no-wrap icon-type/inline-mention/send toolbar without a visibility picker, optional attachment chips and compact conditional date/owner/file controls. Reply/edit context stays visible and locked fields keep their existing payload rules. Full Project Activity chat retains comfortable density. The project summary contract returns `can_post` as a strict boolean; the query-owning UI still normalizes it through `Boolean(...)` before passing it to TanStack Query `enabled`, so rolling or malformed nullable payloads degrade to read-only instead of crashing AppShell.
- In compact density, `Gắn vào` and `Nhắc` are controlled, per-composer disclosures. Pointer-down inside keeps the active disclosure open; pointer-down outside closes it without clearing draft or selection. `Escape` closes the disclosure and stops propagation before the Utility Dock Escape handler, so one key press never also minimizes the project conversation. Listeners are attached only while their disclosure is open, and separately mounted project composers never share disclosure state.

It opens canonical full surfaces and exposes no inline workflow/approval mutation. `ActorRealtimeProvider.tsx` reuses the single personal SSE connection to invalidate `project-discussions` and `utility-project-activity` alongside existing work queries.

## Mandatory Frontend Workflow

1. Start in `frontend/src/app/router.tsx` for route, permission guard, and page ownership.
2. Read the page/module under `frontend/src/modules/<feature>`.
3. Read shared components in `frontend/src/components` and shared module helpers in `frontend/src/modules/_shared` before adding a new primitive.
4. Read API helpers in `frontend/src/lib/api/client.ts` and request-ID normalization in `frontend/src/lib/api/requestID.ts`; do not duplicate fetch/token/refresh/SSE/blob/error-trace logic.
5. Read shared types in `frontend/src/lib/types/domain.ts` compatibility barrel plus bounded `frontend/src/lib/types/domain/*.ts` contracts and status/format utilities in `frontend/src/lib/utils`.
